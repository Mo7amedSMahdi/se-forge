# Phase 6: the starter, the team's routines, and two fixes before them

Branches `fix/save-reminder-monorepo-checks` and `phase-6/starter-skills-docs` (local only). 2026-10-08.

Decisions asked this phase (audit section 9):
- **78:** the starter is a working skeleton, with no features.
- **79:** it's generated by `forge new` from kit templates that the kit tests.
- **80:** the verified stack pairs only.
- **81:** kit-side conformance checks, plus style tests in each project.
- **82:** SemVer tags and a changelog for client releases.
- **83:** a monthly dependency-update ticket, run by an agent.
- **84:** "AI cost" is tokens per ticket.
- **85:** a retro after each release.
- **86:** "Actual" is people's hours.

## Built
**Part A: from the open list**
- **The save reminder.** A Stop hook sends the lead back once to `forge save` when the project's team-repo folder has unsaved changes. It never fires twice in a row (`stop_hook_active`) or again for the same unsaved set, and never for lanes.
- **Per-file checks in a repository holding several services.** A rule may name its folder (`"dir": "backend"`): the command runs there, and `{file}`/`{files}` are relative to it. `dev-environment` documents the layout (`frontend/compose.yaml` includes `../backend/compose.yaml`, the gate chains both services), and the stack guides point to it.
- **A safety fix found while testing that** (below).

**Part B: phase 6**
- **`forge new`** writes the skeleton for FastAPI + PostgreSQL, NestJS + MySQL, .NET + SQL Server, NestJS + MongoDB, and React, alone or as `backend/` + `frontend/`. Every skeleton has:
  - configuration from the environment and problem-details errors;
  - `/health` and style tests (an unknown route and a wrong method answer problem details);
  - migrations set up, but no tables;
  - Dockerfile (dev and production), Compose and `.env.example`;
  - CI for the project's host (a matrix for two services), and a README.

  It never overwrites, writes the settings as a proposal, and runs with the kit version the project pins. When an agent runs it, the hook asks a person; lanes are refused. Bootstrap's after-approval stage runs it for a new repository.
- **`forge metrics <ticket> [--record]`:** the tokens a ticket used, by model and by agent, from Claude Code's local session logs. Lanes are attributed by the ticket their description names, otherwise by the branch they mostly worked on. The lead's tokens count while those agents ran, and each reply counts once. `--record` fills the AI cost cell in `metrics.md`. The ticket and pipeline skills record it at close, and spawns name their ticket.
- **Skills:**
  - `release`: the version and changelog from Conventional Commits, the release and promotion merge requests, and the tag set by a person;
  - `dependency-update`: list, then batch updates (security first, majors as their own tickets);
  - `retro`;
  - `debug-issue`: a failing test first, the root cause, the smallest fix;
  - `onboard-repo`: existing repositories (take stock, the register, a settings proposal, gaps filed as tickets);
  - `handover-docs`.
- **Team docs:** `docs/cheat-sheet.md` (one page) and `docs/metrics.md` (the columns, how AI cost is counted, how to read it).

## Found and fixed along the way
- **A safety gap: paths through a symlink to the repository** (macOS `/var` → `/private/var`, a `~/code` link to another disk). Git names a repo by its real path, so such a path fell outside every repo-relative rule. Writing the stories file, an applied migration or generated code through it was allowed; only secrets, matched by name, were still refused. Every rule path is now resolved first. A regression test fails without the fix.
- **The conformance runner caught template mistakes:**
  - an import-order lint in the FastAPI template;
  - two files the NestJS + MongoDB template's Prettier would reformat.
- **The first version of `forge metrics`** gave ticket 1 two of ticket 2's agents, whose worktrees started on ticket 1's branch. The lead's description of each agent now decides.
- **The estimate skill still called "Actual" the lead's elapsed hours.** It now says people's hours (decision 86).

## Proposals (accepted 2026-10-08, decision 90)
- **`/health` as the skeleton's health route**, answering `{"status": "ok"}`. It's a liveness check that doesn't touch the database; Compose waits for it.
- **A frontend alone includes the backend's Compose file** from `--backend-dir` (default `../backend`).
- **The first release's version** is the owner's choice: `v0.1.0` before launch, `v1.0.0` at launch.
